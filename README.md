# Code → Storybook → Figma

**สร้าง design system ใน Figma จากโค้ดที่รันอยู่จริง ให้ตรงกันแบบวัดได้ — ใช้ได้กับทุกภาษา ทุกเฟรมเวิร์ก**

ชุด skill สำหรับ Claude Code · ถอดมาจากงานจริงที่ทำเสร็จแล้ว (Flutter, 26 ก.ค. – 5 ส.ค. 2026)
ที่ push token เข้า Figma ได้ **138/138 ตัว ตรงทุกค่า** และวาดหน้าจอ 59 เฟรมโดยเทียบภาพกับ
ของจริงทุกใบ

```
โค้ดในแอปจริง  ──►  [ Storybook ]  ──►  Figma
(แหล่งความจริง)      (ไม่บังคับ —        (variable / component /
                     เป็นเครื่องมือวัด     หน้าจอ / flow)
                     สำหรับหน้าจอ)
```

**หลักการเดียวที่คุมงานทั้งหมด:** งานนี้คือ *documentation ของโค้ดจริง ไม่ใช่การออกแบบใหม่*
ถ้าโค้ดทำอะไรน่าเกลียด Figma ต้องน่าเกลียดตาม แล้วแปะป้ายบอกว่าทำไม

## ติดตั้ง

```bash
git clone https://github.com/charun-meedate/code-to-figma.git
cd code-to-figma

./install.sh ~/dev/my-project     # ติดตั้งเข้าโปรเจกต์เดียว
./install.sh --global             # ติดตั้งเข้าเครื่อง ใช้ได้ทุกโปรเจกต์
./install.sh --list               # ดูว่ามี skill อะไรบ้าง
```

จากนั้นเปิด Claude Code ในโปรเจกต์ แล้วบอกว่า *"สร้าง design system ใน Figma จากโค้ดนี้"*

repo นี้มี 3 skill: `code-to-figma` (ตัวหลัก) และ `flutter-widgetbook-catalog` +
`flutter-catalog-page-stories` (สำหรับฝั่ง Storybook ของ Flutter — **repo นี้คือต้นฉบับหลัก
ของสองตัวนี้แล้ว**)

## Claude จะถามอะไรคุณ

**ก่อนแตะอะไรทั้งนั้น** Claude จะสแกนโปรเจกต์ก่อน (หาว่าเป็นภาษาอะไร token อยู่ไฟล์ไหน
มี Storybook อยู่แล้วไหม) แล้วถาม 2 ข้อ โดยเติมคำตอบที่เจอมาให้แล้ว

**ข้อ 1 — จะสร้าง Storybook ด้วยไหม**

| เลือก | ได้อะไร |
|---|---|
| มีอยู่แล้ว ใช้เลย | ใช้ของเดิมเป็นฐานเทียบ |
| สร้างก่อน | แนะนำถ้าจะทำหน้าจอ — มันคือ**เครื่องมือวัด** |
| ไม่ต้อง ไป Figma ตรง ๆ | ทำ token กับ flow ได้เต็มที่ · **แต่หน้าจอจะไม่มีเครื่องมือวัด** |

**ข้อ 2 — จะทำลึกแค่ไหน** (สะสมขึ้นไปเรื่อย ๆ)

| ระดับ | ได้อะไร | ต้องมีภาพไหม |
|---|---|---|
| **T1 token** | variable / text style / effect style ครบ ตรงทุกค่า | **ไม่ต้องเลย** |
| **T2 + component** | master + variant ของ component ที่ใช้ร่วมกัน | ต้องมี |
| **T3 + หน้าจอ** | ทุกหน้า ทุกสถานะ | ต้องมี |
| **T4 + flow** | เส้นเชื่อมทั้งหมด สร้างจาก router ในโค้ด | ต้องมี |
| *(flow-map)* | แผนผังการเดินหน้าจออย่างเดียว ไม่วาดหน้าจอ | **ไม่ต้อง** |

> **T1 คุ้มที่สุดและถูกที่สุด** ไม่ต้องมี Storybook ไม่ต้องถ่ายภาพ ใช้เวลาน้อยที่สุด
> และเป็นส่วนที่พิสูจน์แล้วว่าเครื่องทำได้เองจนจบ · โปรเจกต์ไหนไม่แน่ใจ เริ่มที่นี่

**ข้อ 3 — ถามเฉพาะตอนที่เลือก "ไม่สร้าง Storybook" แต่จะทำหน้าจอ:** จะใช้อะไรเป็นฐานเทียบ
(จับภาพจากแอปจริง / อ่านโค้ดอย่างเดียว) — ทั้งสองทางมีข้อจำกัดที่ **ต้องเขียนลงเอกสารเกณฑ์**

## 4 จังหวะที่คนต้องลงมือเอง

Claude จะ**หยุดรอ**ตรงนี้ ไม่เดินต่อเอง

1. **เซ็นเอกสารเกณฑ์** (`acceptance-criteria.md`) — ก่อนวาดเฟรมแรก
   เพราะ "ตรง 100%" แบบภาพซ้อนกันสนิทเป็นไปไม่ได้ (คนละ text rasterizer)
   ถ้าไม่นิยามไว้ก่อน review จะไม่ผ่านสักหน้าและวนแก้ไม่จบ
2. **approve หน้า pilot** — ทำ 1 หน้าให้จบก่อน แล้วรออนุมัติ ค่อยปล่อยทำที่เหลือ
   เพราะถ้าโครงผิด มันจะผิดเหมือนกันทุกหน้า
3. **approve deviation** — ทุกจุดที่ทำให้เหมือนไม่ได้ ต้องมีเหตุผลและมีคนเซ็น
4. **ตั้งชื่อ version ใน Figma** ที่จุด checkpoint — สคริปต์ทำแทนไม่ได้ (API ไม่รองรับ)

## สิ่งที่ skill นี้จะไม่ทำ

- **ไม่แก้บั๊กในแอป** เจออะไรจดลงไฟล์ findings แล้ววาดตามความจริง
- **ไม่ทำให้สวยขึ้น** โค้ดเป็นยังไง Figma เป็นอย่างนั้น
- **ไม่จัดระเบียบสิ่งที่สุ่ม** หน้าที่ค่าเปลี่ยนทุกครั้ง ให้ใช้ค่าตามภาพอ้างอิงเป๊ะ ๆ
- **ไม่รายงานตัวเลขที่ยังไม่ได้วัด** เขียน `‹MEASURING›` แทน
- **ไม่พูดว่า "token ครบแล้ว" จากการนับ** — จำนวนเท่ากันแต่ค่าผิดได้ ต้อง diff ทีละค่า

## รองรับภาษาอะไรบ้าง

| Stack | ระดับ |
|---|---|
| **Flutter** | **ทำจบครบวงจรมาแล้ว 1 โปรเจกต์** + ทดสอบการดึง token กับอีก 2 · มี skill ฝั่ง Storybook ให้ครบ |
| **React / Next / Vite / TanStack** | **ทดสอบการดึง token กับ 4 โปรเจกต์ production จริง** · ฝั่ง catalog/หน้าจอ ยังเป็น playbook |
| **Vue / Svelte / Angular** | อยู่ในหน้า web เดียวกัน แต่**ยังไม่เคยแตะโปรเจกต์จริง** |
| **SwiftUI / Compose** | บอกวิธีไว้ครบ แต่**ยังไม่เคยรันจริง** — ระบุไว้ตรง ๆ ในเอกสาร |
| **อื่น ๆ ทั้งหมด** | เส้นทางสัมภาษณ์ 5 คำถาม → สร้างตัวดึง token เอง → ยืนยันกับคุณก่อนใช้ |

ที่ข้ามภาษาได้เพราะ **ฝั่ง Figma ไม่รู้จัก framework เลย** มันกินแค่ 4 อย่าง: ค่า token ·
ชื่อ component · ภาพอ้างอิง · กราฟ route · มีแค่การ**ดึง** 4 อย่างนี้ที่ต่างกันตามภาษา

พอทำกับภาษาใหม่จบ skill จะเขียนไฟล์ playbook ของภาษานั้นทิ้งไว้ให้ส่งกลับเข้า repo —
**ยิ่งใช้ ยิ่งครอบคลุมมากขึ้น**
