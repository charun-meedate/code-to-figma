# Adversarial audit — 2026-08-13

Run against `skills/code-to-figma/` on the day it was first published, before
anyone had used it. Three independent reviewers, one lens each, reading the
real files and running the real scripts:

- **internal consistency** — SKILL.md vs the 14 references vs the 7 templates
- **portability** — what breaks on a stack that is not Flutter
- **executability** — can an agent actually follow this from a cold start

**24 findings. 22 fixed, 2 mitigated.** No finding was dismissed.

## Coverage that was lost

The method calls for an **external CLI reviewer** in parallel, on the grounds
that it shares none of the author's context. Both available CLIs failed:
`codex` refused its own default model pending a version upgrade, and `gemini`
had no API key configured. **That independent perspective is missing from this
audit.** Worth re-running when either is available — the three reviewers here
were all the same model family and may share blind spots.

## The four that would have stopped the skill working

1. **Nothing ever obtained the Figma file.** The intake asked about the
   catalog, the scope and the evidence base, and never asked which Figma file
   to write into — a thing no discovery step can produce, because a repository
   cannot know it. Every write tool needs the key. Two reviewers found this
   independently. *Fixed: intake Q4 covers the file, the library policy and
   the build variant; P0 gate 0 blocks on the key resolving.*

2. **No phase for "build a catalog".** The intake offered it, the pipeline had
   nowhere to put it, and P0 required reference images that only it produces.
   An agent answering that question honestly reached the end of the intake
   with no next step. *Fixed: P-1 Catalog, ahead of P0, with the contract in
   `storybook-generic.md` as its exit condition.*

3. **The tokens-only tier jammed on its own gates.** SKILL.md promised it runs
   with no screenshot tooling; `phases.md` listed an unconditional evidence
   gate demanding reference images and a calibrated scale factor. *Fixed: P0
   gates are now tabulated per tier.*

4. **`flows-map` was documented but unreachable** — the branch matrix and the
   profile both listed it, the intake offered only the four cumulative tiers,
   and P6 opened with a precondition it can never meet. *Fixed: offered in Q2,
   with the precondition carved out.*

## The script bug that mattered most

`token_diff.py` keyed tokens on the bare name, so **two families sharing a leaf
name silently overwrote each other** — `spacing.sm` and `radius.sm` went in as
two tokens and came out as one. `sm`/`md`/`lg` across spacing, radius, shadow
and font-size is close to universal on the web.

The report then counted what survived and called it a clean comparison. That
is precisely the defect the script exists to prevent, inside the script that
exists to prevent it. *Fixed: family-qualified keys, and a duplicate now
raises rather than overwrites.*

Three more in the same file, all confirmed by running them:

- **`rule_map` produced one slash regardless of convention** — `color-text-primary`
  became `color/text-primary`, not the `color/text/primary` the web playbook
  promises. Every web token then matched only by loose comparison, so the rule
  path contributed nothing off camelCase. *Fixed.*
- **Only hex parsed.** `rgb()`, `rgba()`, `hsl()` and the bare HSL triplet used
  by the most-copied web token setup all fell through to string comparison and
  were reported as **mismatches** — a false accusation that sends someone to
  change a correct Figma variable. *Fixed, plus an `uncomparable` bucket for
  values genuinely beyond comparison, kept out of the mismatch count.*
- **The P1 gate could never pass on a Figma file that already held variables.**
  Any unowned variable counted as "extra" and there was no way to waive one.
  *Fixed: `ignoreFigma`, with the waived list required in the P1 report.*

## Everything else fixed

Verification told you to open a composite the command never wrote (`--out` was
missing). `tokens.md` offered an MCP call that cannot enumerate a collection.
Discovery classified **React Native as React** and sent it to the web playbook,
where not one instruction applies — Nuxt, Remix, Astro and Solid fell through
entirely, and Compose was missed under a Gradle version catalog. The Storybook
capture recipe did not run: a static build serves nothing on the port the
runner is pointed at, and the runner takes no screenshots without a `postVisit`
hook, which is also the only place the four guards the page demands can live.
`swift-color` truncated any nested-paren value and emitted asset-catalogue
names as if they were colours. The per-screen DONE list required a Figma named
version, which the plugin API cannot do — an unsatisfiable condition on every
screen. The criteria-signing gate contradicted itself with no path for a user
who goes quiet. The session ritual was stated three times, differently. `(P6)`
inside a phase document meant a deviation row, not phase 6. The two tolerance
placeholders that gate every review had no defined value or source. Radius was
sourced from two different files by two different control files. The profile
modelled one frame, one scale and one theme while the web playbook correctly
said a web product has none of those.

## Mitigated, not solved — read before trusting these paths

1. **Nested JS theme objects still have no parser.** The `js-object-*` presets
   capture the leaf key only, so a nested Tailwind/MUI/Chakra config loses its
   key path and drops colliding keys. The presets now say "flat objects only",
   the duplicate warning explains the real cause, and `stacks/web.md` gives a
   one-liner that dumps the resolved theme to JSON instead. **A real
   `format: "js-object"` handler is the proper fix and does not exist yet.**

2. **DTCG aliases and composite tokens are reported, not resolved.**
   `{color.brand.500}`, `var(--x)` and composite `typography`/`shadow` values
   land in the `uncomparable` bucket with an instruction to resolve them first.
   Both `web.md` and `native-mobile.md` say to resolve the chain before
   comparing; **nothing in the toolchain does it.** For a semantic DTCG layer
   that is most of the tokens.

3. Also unbuilt, and named as such where it matters: no `xcassets` walker for
   SwiftUI colours, no `oklch()` support, and no flow-line generator — P6 now
   states plainly that you write that one yourself, and fixes the node-naming
   convention so "delete all lines and regenerate" has a selector.

## Result

`selftest.sh` went from 38 to **45 assertions**, seven of them locking down
audit findings so they cannot return. Green twice.
