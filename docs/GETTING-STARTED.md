# เริ่มใช้งาน — สำหรับคนที่จะเอาไปใช้จริง

เขียนให้ **designer ที่ไม่ได้เขียนโค้ด** อ่านรู้เรื่อง · คุณไม่ต้องรู้ Flutter หรือ React
สิ่งที่ต้องรู้คือ **วิธีคุมความถูกต้อง** และ **จังหวะไหนที่ต้องตัดสินใจเอง**

---

## มันทำอะไรให้

เอาโค้ดที่รันอยู่จริงมาสร้างเป็น design system ใน Figma โดย**วัดได้ว่าตรง** ไม่ใช่ "ดูแล้วน่าจะตรง"

- **token** (สี ระยะ ตัวอักษร) — ตรงทุกค่า พิสูจน์ด้วยสคริปต์ที่เทียบทีละตัว
- **component / หน้าจอ** — เทียบภาพกับของจริง บอกได้ว่าต่างตรงไหน
- **flow** — เส้นเชื่อมสร้างจาก router ในโค้ด ไม่ได้ลากมือ
- **ชื่อ** — ชื่อ frame = ชื่อ class ในโค้ด นักพัฒนาหาเจอจากชื่อที่เขาเขียนเอง

**สิ่งที่มันจะไม่ทำ:** ไม่ออกแบบใหม่ · ไม่แก้บั๊กในแอป · ไม่ทำให้สวยขึ้น
ถ้าโค้ดทำอะไรน่าเกลียด Figma จะน่าเกลียดตาม แล้วแปะป้ายบอกว่าทำไม
**นี่คือฟีเจอร์ ไม่ใช่ข้อจำกัด** — เพราะเป้าหมายคือให้ Figma เป็นหลักฐานของโค้ด ไม่ใช่ความเห็น

---

## ก่อนเริ่ม ต้องมี 4 อย่าง

| ต้องมี | ทำไม |
|---|---|
| **Claude Code** ต่อกับ Figma แล้ว | ไม่งั้นมันเขียนอะไรลง Figma ไม่ได้ |
| **ไฟล์ Figma ปลายทาง** (หรือสิทธิ์สร้างใหม่) | โปรเจกต์โค้ดไม่มีทางรู้ว่าคุณจะเขียนลงไฟล์ไหน — ต้องบอกเอง |
| **ฟอนต์ที่โค้ดใช้ อยู่ใน Figma แล้ว ครบทุกน้ำหนัก** | ถ้าไม่มี งานจะหยุดตั้งแต่ด่านแรก ดูหัวข้อถัดไป |
| **โปรเจกต์โค้ดที่เปิดได้** | ภาษาอะไรก็ได้ |

### เรื่องฟอนต์ — ด่านที่คนสะดุดบ่อยที่สุด

Claude จะเช็คก่อนวาดว่าฟอนต์ที่โค้ดใช้มีใน Figma ไหม **และมีครบน้ำหนักที่โค้ดเรียกใช้ไหม**
(โค้ดเขียนเป็นตัวเลข 400/500/700 แต่ Figma เรียก Regular/Medium/Bold)

**ถ้าไม่มี มันจะหยุดรอ ไม่แทนฟอนต์อื่นให้** — ตั้งใจให้เป็นแบบนั้น เพราะถ้าแทนฟอนต์
ความกว้างข้อความจะเพี้ยนทั้งไฟล์ แล้วการเทียบภาพทุกใบหลังจากนั้นจะวัดของผิดตัว

👉 **เช็คเรื่องนี้กับ admin ก่อนนัดวันส่งงาน** เป็นสิ่งเดียวที่บล็อกได้ทั้งโปรเจกต์

## Claude จะถาม 4 ข้อ — แต่ละข้อแปลว่าอะไร

### ข้อ 1 · จะสร้าง Storybook ด้วยไหม

Storybook = ที่ที่เอาชิ้นส่วนทุกชิ้นมาวางเรียงให้ดูทีละชิ้น โดยไม่ต้องมีเซิร์ฟเวอร์
**หน้าที่จริงของมันในงานนี้คือเป็น "เครื่องมือวัด"** — มันถ่ายรูปทุกชิ้นเก็บไว้
แล้ว Figma เอารูปพวกนั้นมาเทียบว่าวาดตรงไหม

| ตอบว่า | เมื่อไหร่ | ผลที่ตามมา |
|---|---|---|
| **มีอยู่แล้ว ใช้เลย** | โปรเจกต์มี Storybook อยู่แล้ว | ดีที่สุด ไม่ต้องลงทุนเพิ่ม |
| **สร้างก่อน** | จะทำหน้าจอ แต่ยังไม่มี | ได้เครื่องมือวัด แต่**เป็นงานหลายวัน ไม่ใช่ขั้นตอนเล็ก ๆ** |
| **ไม่ต้อง** | จะเอาแค่ token หรือ flow | เร็วกว่ามาก และ**ไม่เสียอะไรเลย** สำหรับ 2 อย่างนั้น |

> **ถ้าจะทำหน้าจอแต่ไม่สร้าง Storybook** จะเสียความสามารถในการวัดหน้าจอไป
> เพราะสถานะอย่าง "โหลดไม่สำเร็จ / ไม่มีข้อมูล / ข้อความยาวเกิน" **แอปจริงบังคับให้เกิดไม่ได้**
> มีแต่ Storybook ที่ทำได้ · Claude จะถามต่อว่าจะใช้อะไรแทน และจะเขียนข้อจำกัดนั้นลงเอกสารเกณฑ์

### ข้อ 2 · จะทำลึกแค่ไหน

| ระดับ | ได้อะไร | ต้องถ่ายภาพไหม | เหมาะกับ |
|---|---|---|---|
| **T1 token** | สี ระยะ ตัวอักษร เงา ครบ ตรงทุกค่า | **ไม่ต้องเลย** | **เริ่มที่นี่ถ้าไม่แน่ใจ** |
| **T2 + component** | master + variant ของชิ้นส่วนที่ใช้ร่วมกัน | ต้อง | มี design system อยู่แล้วอยากให้ตรงกับโค้ด |
| **T3 + หน้าจอ** | ทุกหน้า ทุกสถานะ | ต้อง | ทำ handover เต็มรูปแบบ |
| **T4 + flow** | เส้นเชื่อมทั้งหมดจาก router | ต้อง | ต้องการภาพรวมทั้งระบบ |
| **flow-map** | แผนผังการเดินหน้าจออย่างเดียว ไม่วาดหน้าจอ | **ไม่ต้อง** | อยากเห็นว่าแอปเชื่อมกันยังไง แบบถูก ๆ |

> **T1 คุ้มที่สุด** ไม่ต้องมี Storybook ไม่ต้องถ่ายภาพ เสร็จเร็วสุด และเป็นส่วนที่
> **เครื่องทำเองได้จนจบ** (ส่วน component ต้องมีคนตัดสินใจทุกตัว)
> · ในรอบที่พิสูจน์มาแล้ว T1 ได้ token ตรง 138 จาก 138 ตัว

### ข้อ 3 · จะใช้อะไรเป็นฐานเทียบ

ถามเฉพาะตอนที่ตอบข้อ 1 ว่า "ไม่สร้าง Storybook" แต่จะทำหน้าจอ · ทั้งสองทางมีข้อจำกัด
และ **Claude จะเขียนข้อจำกัดนั้นลงเอกสารเกณฑ์ให้คนอ่านทีหลังรู้** ว่าที่เซ็นไปน่าเชื่อแค่ไหน

### ข้อ 4 · 3 อย่างที่โปรเจกต์ตอบให้ไม่ได้

1. **ไฟล์ Figma ไหน** — วางลิงก์ หรือให้มันสร้างใหม่
2. **ใช้ library ของบริษัทได้ไหม** หรือทำแยกจากโค้ดล้วนก่อน
3. **build variant ไหนเป็นตัวอ้างอิง** (ถ้าโปรเจกต์มีหลายตัว เช่น dev/prod)

ถ้าเป็นงานเว็บจะถามเพิ่ม: **จะทำ breakpoint ไหนบ้าง** และ **theme ไหนบ้าง**
(เว็บไม่มี "ขนาดจอเดียว" การเลือกเงียบ ๆ ให้ 1 ขนาดแล้วบอกว่าครบ = โกหกกลาย ๆ)

## 4 จังหวะที่คุณต้องลงมือเอง

Claude จะ**หยุดรอ**ตรงนี้ ไม่เดินต่อเอง — นี่คือส่วนที่ทำให้งานเชื่อถือได้

**1 · เซ็นเอกสารเกณฑ์ ก่อนวาดเฟรมแรก**

"ตรง 100%" แบบภาพซ้อนกันสนิทเป็นไปไม่ได้ — Figma กับตัว render ของแอปคนละตัว
คนละ dictionary ตัดคำ **ถ้าไม่นิยามไว้ก่อนว่าอะไรนับ/ไม่นับ review จะไม่ผ่านสักหน้าและวนแก้ไม่จบ**

เอกสารมี 4 ส่วน: **A** อะไรต้องตรงเป๊ะ · **B** อะไรไม่นับเป็นความผิด (เซ็นครั้งเดียว) ·
**C** วิธีตรวจต่อหน้า ~10 นาที · **D** แบบไหนเรียกว่าจบ

**2 · approve หน้า pilot**

ทำ 1 หน้าให้จบก่อน แล้วหยุดรอคุณอนุมัติ ค่อยปล่อยทำที่เหลือ
**เพราะถ้าโครงผิด มันจะผิดเหมือนกันทุกหน้า** · ในรอบที่พิสูจน์มา pilot กลับมาพร้อมคำสั่งแก้ 1 จุด
— จับได้ตอน 1 หน้า ดีกว่าจับได้ตอน 16 หน้า

**3 · approve deviation**

ทุกจุดที่ทำให้เหมือนไม่ได้ ต้องมีแถวในบันทึกพร้อมเหตุผล **ห้ามมีความต่างที่ไม่ได้บันทึก**

**4 · ตั้งชื่อ version ใน Figma** ที่จุด checkpoint — สคริปต์ทำแทนไม่ได้ (API ไม่รองรับ)

## เมื่อ Claude หยุด แปลว่าอะไร

| มันบอกว่า | แปลว่า | คุณทำอะไร |
|---|---|---|
| "ฟอนต์ X ไม่มีใน Figma" | ด่านแรกไม่ผ่าน | ขอ admin อัปโหลด **อย่าสั่งให้ใช้ฟอนต์อื่นแทน** |
| "ID นี้หาไปจาก Figma" | มีคนย้าย/ลบ node ที่มันสร้างไว้ | บอกว่าตั้งใจลบไหม · มันจะไม่สร้างใหม่เงียบ ๆ |
| "token family นี้ไม่มีในโค้ด" | เช่นไม่มี shadow token เลย | **นี่คือ finding ไม่ใช่ช่องว่างให้เติม** ตัดสินใจว่าจะแจ้ง dev หรือรวบค่าที่กระจายอยู่ |
| "ยังไม่ได้วัด เขียน ‹MEASURING› ไว้ก่อน" | มันไม่เดาตัวเลข | ให้มันวัดจริงก่อนเอาไปรายงานใคร |
| "เจอบั๊กในแอป" | มันจะวาดตามความจริง + จดไว้ | **อย่าสั่งให้แก้โค้ด** ส่งให้ dev ทีหลัง |
| "เกณฑ์ยังไม่มีลายเซ็น" | ด่าน 1 ยังไม่ผ่าน | ถ้าอยากให้ไปต่อ มันจะทำแค่ pilot แล้วหยุด และจดว่ายังไม่เซ็น |

## วิธีตรวจว่าที่ได้มาเชื่อถือได้

ถาม 4 คำถามนี้ ใช้ได้ทุกครั้งไม่ต้องรู้โค้ด

1. **"gate ไหนถูกรันจริง gate ไหนไม่ได้รัน"**
   — "เขียวแล้ว" อาจจริงแต่ไม่ครบ · เคยมีเคสรายงานผ่าน 1,613 ข้อ ทั้งที่ข้อถ่ายภาพไม่ถูกรันเลย
2. **"ต่างตรงไหน ไม่ใช่ต่างกี่เปอร์เซ็นต์"**
   — เคยมีเฟรมได้ 0.32% ทั้งที่ปุ่มเลื่อนผิด 320 จุด เพราะมีแผ่นทึบบัง
3. **"ค่านี้อ่านมาจากไฟล์ไหน บรรทัดไหน"**
   — ทุกค่าต้องมาจากโค้ด ไม่ใช่จากการวัดภาพ
4. **"รันซ้ำอีกรอบให้หน่อย"**
   — เขียวรอบเดียวไม่นับว่าเขียว

**และข้อสำคัญที่สุด:** ถ้ามันบอกว่า "token ครบแล้ว 138 ตัว" ให้ถามว่า **เทียบทีละค่าหรือนับจำนวน**
— จำนวนเท่ากันเป๊ะแต่ค่าผิดได้ และเคยเกิดขึ้นจริง

"ห้ามจัดระเบียบสิ่งที่สุ่ม" (บางหน้าค่าเปลี่ยนทุกครั้งที่โหลด ให้ใช้ตามภาพอ้างอิงเป๊ะ ๆ) ·

## รองรับภาษาอะไรบ้าง — และตรงไหนที่ยังไม่พิสูจน์

|---|---|

| **React / Next / Vue / Svelte / Angular** | มี playbook เต็ม ยังไม่มีใครรันจบทั้งรอบ |
| **React Native** | ตรวจเจอแยกจาก React แล้ว ส่งไป playbook ฝั่ง native |
| **SwiftUI / Compose** | บอกวิธีไว้ครบ **แต่ยังไม่เคยรันจริง** — เขียนกำกับไว้ในเอกสาร |
